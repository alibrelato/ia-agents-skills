# MikroTik Backup File Analysis

Interpret and extract information from backup files generated by RouterOS v6/v7, both binary (`.backup`) and text (`.rsc`).

## Core concepts
- **`.backup` (binary)**: native and proprietary format. It is NOT readable text. It can only be restored by RouterOS itself on the **same version** (minimum v7.1 for v7 files) and **same architecture/device**.
- **`.rsc` (text)**: output of the `/export` command, readable and editable. It can be imported in any compatible version via drag-and-drop or `/import`; great for auditing.
- Always recommend BOTH: `/system backup save name=<name>` and `/export file=<name>`.

## 1. Collect and identify the file
- Generate backup: `/system backup save name=backup-2026-08-20`.
- Generate export: `/export file=export-2026-08-20`.
- List files: `/file print`; locate size/version of the backup (`/system backup` shows truncated metadata).
- Download via WinBox/SSH (`/file download`) or FTP, keeping integrity.

## 2. Inspecting a `.backup` file
- Do not try to open with a text editor (corrupted binary/NULs).
- Tools:
  - MikroTik v7 only supports binary; there is no native reader outside RouterOS.
  - If needed: use strings/characterization only for informational confirmation (not reliable for config extraction).
- Reliable method: **restore in a lab/virtualizer** with the same RouterOS version and export `.rsc` from there. E.g.: CHR in VirtualBox/VM with same build → `/system backup load name=<file>` (anonymous) → `/export file=recovered` → read.
- Warn about the risks of restoring a backup in production (complete overwrite of the current configuration).

## 3. Reading the `.rsc` file (export)
Typical structure (readable text):
- Header comments with date/genre (e.g.: `# exported by admin`).
- Sections per subsystem: `/interface`, `/interface bridge`, `/ip address`, `/ip route`, `/ip firewall`, `/ip dhcp-server`, `/user`, `/system`.
- Each line = one item with `add <param>=<value>`.
- `disabled=yes` props indicate an inactive item (important when auditing).

## 4. Extracting useful information
- Model/version in the export (if present) or headers; otherwise infer from used features (WireGuard → v7+).
- Inventory: Interfaces, IP addresses, routes (default/static/dynamic), NAT, firewall rules, DHCP pools/leases, users/groups, enabled services.
- Identify sensitive configurations: hashed passwords (Salted SHA-256 in v7+/recent v6), PSK, VPNs, and mask them as `***` when documenting.
- Detect inconsistencies: rules with `disabled`, references to inexistent interfaces, IPs out of range, rules inside lists.

## 5. Safe restore
- In production: anonymous backup (without passwords) where possible.
- Restore in maintenance: `/system backup load name=<file>` reboots the device.
- Always keep a previous backup and test in a lab before applying to critical equipment.
- Non-destructive alternative: generate only "commands" from the `.rsc` or re-implement specific blocks (skill `mikrotik-configuration`).

## 6. Support tools/approaches
- External scripts (Python/bash) to format `.rsc` into a summary table.
- Compare two backups/exports (diff) to detect changes between periods.
- Syntax validation: `/import` on a test VM/CHR before running in production.

## Expected output
Structured backup summary: inferred model/version, table with interfaces/IPs/routes/firewall/DHCP/users, list of sensitive items (masked), detected problems and recommendations (including `.backup`→`.rsc` conversion when necessary).
